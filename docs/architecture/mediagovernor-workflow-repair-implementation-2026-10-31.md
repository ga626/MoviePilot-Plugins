## 四、实施过程中新增发现：不能只删 cleanup 参数

对照官方参考 `app/chain/transfer/workflow.py`、`records.py`、`plan.py` 与 `app/chain/storage.py` 发现：普通 manual_transfer 的执行流程本身还有历史门。旧成功记录可能跳过；旧失败记录可能触发历史目标删除。只不传 cleanup_dest_fileitem 并不能证明旧入口不会被提前清理。

因此执行适配做了明确修改：

1. 使用官方 `manual_transfer(preview=True)` 计算目标，不执行它的历史工作流。
2. 读取已确认来源、ID、类型和剧集组的数据库详情；若实际详情身份不一致就拒绝。
3. 使用公开 `TransferChain.transfer` 单文件接口，不调用私有 helper、不改宿主源码、不导入 sdk._legacy。采用冻结 preview 输出的 org_string、季集、episode_end、part、resource_team、customization、apply_words。
4. 该单文件接口先 `preview=True`，返回 target_item 必须与冻结目标（含 storage）一致，才允许 `preview=False`。不传 force、cleanup 或 reorganize；当前目录非硬链接策略就拒绝。
5. 全部应有入口先回读证实；再按单项许可，通过公开 `StorageChain.delete_file` 删除列出的文件 DTO，不调用 delete_media_file，不处理父目录。
6. 每阶段保存 repair_result；失败消费旧许可、保留逐项回执，必须新检查/新计划。成功也要回读确认，不把原生返回成功直接算完成。

本地参数测试曾实际抓到“只设置 total_episode、没有设置 end_episode”的错误，现已显式传末集并回归通过。这正是要验真实 DTO 而不是仅看参数名字的原因。

**边界**：公开入口存在和本地参数通过，不证明 NAS 的模块实现、剧集详情、重命名模板和存储 provider 已通过。接口没有跨进程原子事务；外部程序在检查和执行之间并发改媒体的竞争不能由插件锁彻底消除。真实写入验收须暂停同范围其他整理活动，并用最小获准样本验证。

## 五、额外保护与兼容处理

- 本地 stat 也可能受挂载 I/O 影响，现改为批量、受统一期限和配额管理；失败一次后本轮停用加速，回退大小候选，不把索引失败当空库。
- 源指纹加入可用的 dev/ino；同大小同时间替换源文件也使修复许可失效。
- 生成和执行计划各重读下载保护范围，目标或旧入口落入保护范围就拒绝，避免预览后配置变动触及下载原件。
- 旧版自动确认仍降为候选；人工确认保留。新源文件集、目录配置、命名规则、映射等使相应 preview 失效，不因仅枚举顺序变化无谓失效。
- 后台预览线程、修复锁和残留只读线程参与 stop/hot-reload 判断，旧实例未退出时不叠加第二实例。
- UI 沿用当前主题变量、色彩和布局，没有视觉重设计。新增整簇选择、覆盖与时间说明、映射字段、后台 preview 状态和独立清理许可；修复回执状态有专门说明。
- 新版本资源路径为 dist/v5.1.1/assets，构建移除旧 dist 生成物；旧源码/提交仍可恢复，不手改压缩资源。
- 没有引入新依赖、模型服务、账号、网络配置、第二个写入器或长期后台服务。

## 八、下一步与真实停止点

1. 先完成后续 PR/CI 和候选交付授权；当前不绕发布标志/保护，不公开本包。
2. 对同一候选安装加载并回读版本、代码/制品身份、默认只读和 AI 关闭。核实际宿主 SDK、strict list/get、stat 观察域及 native preview/transfer/delete_file 合同。
3. 用此前人工复核真样本核对完整清单、解析摘要、正确候选、不同源覆盖、错链和缺失；同时检查正常对照不误报。混包、S0、绝对集号、双集、不支持格式单列。
4. 只读先测无变化复查、单项确认、停止、重开、超时后在途配额、分页完成和局部队列，不先上全量 AI。
5. 用户确认具体目标、源/旧/新入口计划和清理范围后，才关闭只读执行一个最小受管样本；检查源和邻居资料未变、正确新链、批准旧链消失、再查无重复动作。该许可不是批量写入授权。
6. 最后才扩大范围。AI 如确需实验，先明确连接、模型和预算，仅比较剩余疑难摘要、batch1与3–5；记录供应商真实 usage、墙钟和候选质量。本轮未做这些调用，没有节费比例或最优超时保证。
