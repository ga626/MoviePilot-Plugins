# MediaGovernor 5.1.0 本地候选与现场验收清单

日期：2026-10-30。状态：本地候选准备；不是 NAS 已安装、正式发布或用户验收。

## 本轮完成的事

将物理优先源码、数据库候选、人工身份/文件归属、安全对账及失败诊断整理为同一候选。版本、市场版本历史、前端 package、后端 render 路径、页面标识和 Vite 资源目录统一为 5.1.0。它是本地待验版本号，不表示市场已有此版本。

新增默认 `read_only=true`。后端 API 与服务执行入口均阻止媒体修复；页面仍能检查、搜索、确认身份和生成预览，但没有最终执行按钮。配置遗漏或不为布尔 false 时按只读处理；热重载旧 worker 未退出时，也会同步只读与 AI 安全默认值。只读允许保存插件私有状态、查询公开元数据；不是完全离线，也不是禁止 SQLite 写入。AI 由另一个默认关闭的开关控制。

选择后端强制只读，而不是仅在 UI 上提醒，是为了即使有人保留了旧请求或修复 token，也不能绕过本轮“不写媒体”的边界。同一包以后可以在明确单项修复许可后关闭只读，不必为验证写入换另一份二进制；关闭只读不替代预览和单项执行确认。

没有创建新插件，没有变动 NAS、代理、下载器、PT 或媒体；没有提交到 GitHub、触发 CI 或公开 Release。市场条目的既有 `release=true` 未改变；本轮禁止推送/合并市场变更，否则现有 main 发布工作流可能自动发布。这不是通过本地候选准备获得的公开发布许可。

## 源码与制品绑定

延续现有未合并分支 `codex/media-governor-layered-cache-r1`。提交范围只包括本任务源码、对应测试、5.1.0 前端产物、市场版本记录和本文；不收录用户其他未跟踪研究资料、运行日志、SQLite、截图或秘密。

打包必须使用仓库既有 `.github/scripts/build_plugin_release_zip.py`，从已提交 HEAD 读取文件，不从脏树读源。包名为 `mediagovernor_v5.1.0.zip`，仅在 ignored `local/candidates` 保存。打包后须逐文件核对 ZIP 与 HEAD、检查目录结构、默认只读、版本/联邦入口及哈希，并保存本地回执。

有未跟踪的历史报告不等于包源不干净；关键是所有受影响运行源码与 dist 已提交，包来自同一 Git 对象且字节对账。不得将未跟踪资料偷偷加入候选来制造整树“干净”。本地候选 SHA、ZIP SHA、检查命令和状态记录在 ignored 候选回执中，不给这份文档伪造自己的提交 SHA。
