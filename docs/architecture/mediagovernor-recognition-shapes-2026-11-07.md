# 识别阻断同类修复与扩大现场验收

## 范围与保留合同

修复 5.1.2 现场暴露的别名遗漏、身份/映射耦合、目录参与逐文件关系配对，以及详情冲突不可诊断问题。AI 关闭、只读；不更改代理、宿主、下载、媒体或历史，不把待定算正常。不为具体作品、路径或 ID 编写特例。

调用链仍为发现源与库 → 当前物理关系 → 独立源命名与数据库核验 → 官方只读 preview → 逐文件对账。verified 不是 confirmed，也不授予媒体写入许可。依赖、CI 和发布合同保持不变。

## 可证伪假设与反馈

1. 数据库别名在 identity_from_media/public_identity 投影时丢失；用真实 SDK MediaInfo 形状带 en_title/names 的红绿测试定位。
2. 推断集号和作品身份共用拒绝条件；用单标题、多季、跨年、推断尾集测试，分别验证身份与执行映射。
3. 原盘/目录无大小或 inode，导致全库候选；固定 2187 个库条目形状并断言目录关系探针为零。
4. 详情冲突可能是适配、数据源或真实字段不一致；回执只留字段状态与公开身份键，不能在未见原始冲突前猜原因。
5. 人为截 8 个搜索结果被误当满页、fallback 重置诊断；分别用大结果集、详情失败和原生失败回归证伪。

## 两个实施方案与取舍

A：在原 if 上放宽年份/标题/集号条件，选择第一个候选。改动少，但多解、映射和身份仍混在一起，错误能直达后续预览，不能采用。

B（采用）：保留当前单一适配层；提炼有界可信别名与源身份投影、字段级详情比较、独立映射说明。源候选搜索去掉人为八项截断，按当前返回集合和明确查询/详情预算给出唯一匹配或具体待定；不宣称查遍数据库。最多核对 64 个公开候选；唯一精确匹配回读一项详情，只有译名时最多回读三项同类型/年份详情，超过预算明确待定，不选第一项。目录绝不进入文件对合同，原盘能力缺口显式呈现。复杂度留在可测纯函数和现有 adapter，不新增账本/客户端/依赖。

## 回归与迁移

先固定本轮失败形状，再改实现。提高身份策略版本使旧自动核验和候选重新检查；人工确认保留。字段回执不保存原始详情、路径、供应商异常正文或文件列表。新增 mapping 说明不自动写 season/epformat，执行仍用官方 preview 和已有单项许可合同。

覆盖正常/异常：多语言别名、同名错年/错类型/多 ID、电影多 part、多季和跨年、无年份、裸集号、原盘、空/失败详情、身份来源/类型/ID变化、搜索预算/超时、缓存到期/并发人工改选，以及原盘关系调用数量。新 SHA 下运行一次插件候选回归与必要前端构建，再走 PR CI。

## NAS 冻结验收清单

同一新候选、AI=false、read_only=true，不人工确认来促成 PASS，不造缺失或错分类数据。正常电影、正常剧集、缺失/未证实关联、已知错分类，每类目标 2–3 个真实源容器；样本集覆盖别名、原盘、多季、推断集号和详情冲突。优先完整运行一次当前可发现范围，随后只读逐样本交叉复核。

每项记录源指纹、身份/依据/字段回执、映射就绪性、源数量/已证实关联/未证实、官方 preview 覆盖、最终结论/阶段错误/耗时。源没有某类真值时明确“样本不足”，不能把未知改名为已知错分类。预定样本与新发现均保留，不因失败换样凑通过。完整跑完、准确性、覆盖、支持边界分别判定；没有媒体写入。

5.1.2 原资产/tag 不覆盖。需要公开候选才能安装时只发布同一包的未验收只读试用，不升级为稳定/正式验收。源码、制品、公开与 NAS 身份分别绑定回执。
