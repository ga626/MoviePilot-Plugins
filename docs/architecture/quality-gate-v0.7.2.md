# MediaGovernor v0.7.2：最后一道整理质量检查

## 这次修复的真实问题

v0.7.1 为避免“一键检查”长时间没有响应，改成只读取已经保存的作品身份。这个取舍造成了反效果：较早的失败历史往往没有完整身份，于是页面把大量空记录都显示为“无法自动识别”。“刷新结果”也只是重新读取空记录，并没有重新核对。

v0.7.2 改为逐条真实核对。每次浏览器请求只处理一条历史记录，完成后立即保存可展示的、脱敏的结论；前端随后再请求下一条。因此一条识别较慢不会堵住整批任务，也不会丢失已完成进度。

## 用户看到的流程

1. 点击“**一键检查全部（不改文件）**”。这是启动检查，不是修改媒体。
2. 页面立即显示“已完成 / 总数”、百分比和“正在核对第几条”。每一条完成后进度都会前进。
3. 需要暂时停止时点击“**暂停检查**”。已完成结论保留；点击“继续检查”从下一条开始。
4. 已经找到中文作品身份的项目才显示成单独卡片，卡片说明具体问题和下一步。
5. 没有任何可靠身份的历史记录只显示数量与原因，不再伪装成一排没有片名的影片卡。系统不会把原始文件名猜成影片名。
6. 只有用户打开某张已确认卡片、确认处理方案并再次确认后，才可能创建一个硬链接。检查和方案生成本身都是零写入。

## 实际检查什么

### 失败的整理记录

- 优先复用已保存的媒体身份；没有时，只在本次检查中调用 MoviePilot 原生识别链。
- 识别到作品后，以 MoviePilot 原生整理链做硬链接预演；预演失败会明确显示“暂不能处理”，不会创建文件。
- 预演通过时显示作品名和“可生成方案”；真正创建硬链接仍需用户确认。

### 显示成功的整理记录

成功不再自动等于正确。历史回溯和后续完成事件都会纳入质量闸门，至少核对：

- 是否有可靠的作品身份；
- 历史中是否记录了整理方式；
- 记录的整理方式是否为硬链接。

若这三项可证明均正确，记录不打扰用户。若不是硬链接或没有整理方式，才生成带作品名称的问题卡。

## 不会假装做到的事

当前 MoviePilot 对插件公开的历史与预演合同，不能在不保存/展示真实路径的前提下，让插件可靠比较“实际目标目录”和“应该目标目录”；也不能仅凭一批下载文件就判断某季一定少集。因此 v0.7.2 不会把这两类“无法证明”的情况伪报为错误。

后续如果宿主能提供脱敏的比较结果（例如仅返回 `destination_matches`）或明确的连续集数事实，质量闸门可增加“归类位置不符”和“集数明确缺失”两个已确认错误类别。届时仍只保存布尔结论和媒体身份，不保存媒体路径、文件名、下载信息或运行日志。

## 设计依据与边界

- MoviePilot 官方 V3 文档要求插件使用基类持久化数据接口保存小型可序列化状态，动态 API 和 Vue 联邦页面使用宿主传入的 `pluginId`/`api`，运行数据不能写回源码目录。[官方文档](https://github.com/jxxghp/MoviePilot-Plugins/blob/main/docs/Plugin_Development.md)
- 可恢复任务采用“离散步骤、持久游标、单项完成后 checkpoint”的模式；这正是本版本将批量检查拆成 `/audit`、`/audit/next`、`/audit/pause` 的原因。[River Queue：Resumable Jobs](https://riverqueue.com/docs/resumable-jobs)
- 检查与预演不移动、删除、改名、覆盖原文件，也不修改下载器、代理或目录规则。修复入口仍固定为用户二次确认后的单条硬链接。

## 实施路线图

```mermaid
flowchart LR
  P1["P1 历史纳入\n成功与失败记录"] --> P2["P2 逐条可恢复检查\n进度、暂停、继续"]
  P2 --> P3["P3 仅展示真实问题\n生成零写入方案"]
  P3 --> P4["P4 宿主合同扩展\n目录/集数的可证明检查"]
```

- **P1**：以 MoviePilot 历史和完成事件为输入，分别记录成功与失败，而不是把“成功”排除在检查外。验收是两类记录都会进入可恢复队列。
- **P2**：每次 API 请求领取且只处理一条；完成后写 checkpoint。验收是页面可见进度，暂停/重载后未完成项可以继续。
- **P3**：仅把有中文作品身份和具体结论的记录做成问题卡；预演通过后才允许生成方案。验收是空身份记录不再形成空卡、方案和实际修复仍分两次确认。
- **P4**：等待宿主提供“目标位置是否匹配”和“已确认的连续集数”这类脱敏事实。验收是新问题类别只基于可复核的布尔/计数结论，不保存路径。

## 详细执行步骤

变更边界：是否改代码：是；只改本插件的状态机、动态 API、Vue 页面、测试、构建产物和文档，不涉及媒体文件、下载器、代理或目录规则。

1. **P1 收集历史**：做什么是由周期服务按页读取成功和失败历史；怎么做是投影为身份、事件类型和整理方式，不读取或保存文件路径。输入是 MoviePilot 历史，输出是脱敏质量记录，验收是两类记录都进入队列。依赖 MoviePilot 的公开 `TransferHistoryOper` 查询合同；代码变更：是，只限插件状态机。
2. **P2 建立队列**：做什么是启动可恢复检查；怎么做是仅写入待检查编号和游标。输入是历史编号，输出是持久化任务状态，验收是不触发识别或硬链接操作。依赖 P1 已获得的历史记录；代码变更：是，只限插件数据。
3. **P2 处理一项**：做什么是核对一条记录；怎么做是前端调用下一项接口，失败记录最多调用一次原生识别和一次零写入预演，成功记录只检查可证明的身份和硬链接方式。输入是单条历史，输出是单条结论，验收是每项完成即保存、重载不会遗漏。依赖 P2 队列；代码变更：是，不触碰媒体文件。
4. **P3 呈现与处理**：做什么是展示真实问题；怎么做是身份不足只汇总，有名称的卡片才可以生成方案。输入是脱敏结论，输出是中文问题卡，验收是空身份不成卡、方案确认后才执行单条硬链接。依赖 P2 结论；代码变更：是，只限前端页面。
5. **P4 验证与扩展**：做什么是验证本版本并保留目录/集数检查的扩展点；怎么做是运行纯逻辑、构建、版本和 CSS 门禁，候选再在真实宿主加载。输入是候选代码，输出是验收回执，验收是所有门禁通过且无路径泄露。依赖 P1-P3；代码变更：是，未来目录/集数功能依赖新的宿主合同。

## 验收清单

- 中断在某一项时，下一次加载会把未完成项放回待检查队列；不会遗漏。
- 暂停/继续不清空已经完成的结论。
- 单次 `/audit/next` 最多做一次原生识别和一次硬链接预演。
- 只保存作品身份、检查状态和脱敏结论；不保存路径、`src_fileitem`、目标目录或原始文件名。
- 成功记录也会进入历史质量回溯；可证明的非硬链接会显示为问题，不能证明的情况不伪报。

## 已知限制

- 当前宿主没有给插件足以比较真实与预期目录的脱敏结果；此项保持“无法验证”，不做猜测。
- “少集”只有在宿主提供明确连续集数事实后才可确认为错误；一批下载尚未完整不能当作少集。
- 当前工作区的默认 Python 缺少 `pytest`，所以本轮已逐个执行同一测试文件中的 17 个纯逻辑合同测试；候选安装前仍需要使用 MoviePilot 宿主解释器运行 pytest 并在真实 V3 宿主加载一次。
