# MediaGovernor 架构与安全边界

## 产品职责

MediaGovernor 是 MoviePilot V3 整理链路之后的质量检查插件。它提供“找对作品”和“整理正确”两个工作台：把失败整理来源包压缩为不含路径的证据摘要，再用 MoviePilot 的官方预览与受控重整修正已确认的硬链接。它不是下载器、媒体服务器、文件管理器，也不替代 MoviePilot 的媒体识别或整理链。

## 判断顺序

1. 失败整理先读取来源包的有限目录摘要、名称线索、季集模式和视频/字幕数量；检查小并发、逐条呈现，可暂停或停止，不持久化文件名/路径。
2. 以来源文件、目录名和代表性文件名调用 MoviePilot 原生识别；再发现当前注册来源、搜索候选并查询详情。标题、年份、类型、季集或集数规模冲突时必须停在用户选择。
3. 已确认身份进入整理审计：`transfer/manual/history` 确认旧成功历史，`transfer/manual/target-path` 确认唯一规则目标，`transfer/manual` 的 `preview=true,reorganize=true` 生成零写入逐文件方案。
4. 只有旧成功硬链接可归因、目标唯一、预览完整且无重复集号时，才能在用户确认后调用 MoviePilot `transfer/manual` 的 `transfer_type="link"`、`reorganize=true`。旧目标清理由 MoviePilot 官方完成；插件不自行删除文件。

## 状态与隐私

运行结果只在当前页面内存中保存：作品身份、候选证据、文件数/集号摘要、预览统计和回执版本。不得保存真实路径、完整文件名、`FileItem`、宿主数据库对象、Cookie、订阅、节点或 PT 信息。

历史 `mode` 是“当时如何整理”的说明，不是当前文件状态。旧版本错误读取 `transfer_mode`/`transfer_type` 造成的批次状态通过 schema 升级作废，必须重新检查，不能迁入新结论。

## 不支持的动作

- 不自行复制、移动、删除、重命名或覆盖文件；
- 不改变下载器、代理、媒体目录和原有整理规则；
- 不绕过 MoviePilot 官方重整入口删除旧目标；
- 不按单部作品编写例外规则；
- 不把 AI 猜测作为执行依据。当前没有稳定的第三方插件 AI 合同，因此全库检查默认零 AI 调用。

## 验证合同

候选至少需要证明：版本三处一致、目录未写死、检查逐条可见且可暂停、冲突候选不能自动执行、历史/目标/预览三段审计齐全、预演与执行分离、前端构建产物可由 V3 联邦加载。真实宿主验证仅可使用只读检查或 `preview=True`；任何真实媒体写入都需要独立明确授权。
