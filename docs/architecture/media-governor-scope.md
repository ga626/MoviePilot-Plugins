# MediaGovernor 架构与安全边界

## 产品职责

MediaGovernor 是 MoviePilot V3 整理链路之后的质量检查插件。它把整理历史和当前可读取的源/目标文件包压缩为不含路径的证据摘要，按可靠媒体身份聚合为作品卡片。它不是下载器、媒体服务器、文件管理器，也不替代 MoviePilot 的媒体识别或整理链。

## 判断顺序

1. 复用 MoviePilot 历史中的媒体来源、媒体 ID、类型、标题和季信息；失败记录缺身份时，才调用一次 MoviePilot 原生识别。
2. 对成功整理，只在源和目标文件包均可核验且存在明确差异时建立问题：目标入口缺失、视频数减少或已识别剧集减少。移动整理后源文件自然不存在，不会因此形成问题卡。
3. 对失败整理，只有源仍可访问、身份可靠且 MoviePilot 原生预演通过，才可以生成方案。
4. 用户选定目标时，前端从 `GET /api/v1/storage/directories` 读取当前目录；后端再次以当前 `DirectoryHelper.get_library_dirs()` 验证名称、存储和路径。真实路径只在单次原生调用中存在，持久化计划只保存目标名称和不可逆指纹。
5. 执行时固定使用 MoviePilot `TransferChain.manual_transfer` 的 `transfer_type="link"`、`reorganize=False`、`sync_extra_files=False`。计划过期、目标变化、预演失败或无法证明安全性时一律停止。

## 状态与隐私

`GovernanceQueue` 保存脱敏的事件投影、作品身份、计划状态与回执版本；`BatchAudit` 保存本轮游标、作品问题和文件数/集号摘要。两者都不得保存真实路径、完整文件名、`FileItem`、宿主数据库对象、Cookie、订阅、节点或 PT 信息。

历史 `mode` 是“当时如何整理”的说明，不是当前文件状态。旧版本错误读取 `transfer_mode`/`transfer_type` 造成的批次状态通过 schema 升级作废，必须重新检查，不能迁入新结论。

## 不支持的动作

- 不自行复制、移动、删除、重命名或覆盖文件；
- 不改变下载器、代理、媒体目录和原有整理规则；
- 不自动删除旧目标；
- 不按单部作品编写例外规则；
- 不把 AI 猜测作为执行依据。当前没有稳定的第三方插件 AI 合同，因此全库检查默认零 AI 调用。

## 验证合同

候选至少需要证明：版本三处一致、目录未写死、目标选择会失效保护、文件差异才形成成功历史的问题卡、每次检查可重新开始、预演与执行分离、前端构建产物可由 V3 联邦加载。真实宿主验证仅可使用只读检查或 `preview=True`；任何真实媒体写入都需要独立明确授权。
