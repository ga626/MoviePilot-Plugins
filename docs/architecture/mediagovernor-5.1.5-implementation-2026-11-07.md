# MediaGovernor 5.1.5：三批根因修复与候选边界

日期：2026-11-07。基线：5.1.4，`4cbbc11720ae0e7fdc715c3d17d2bcac725b3173`。

## 范围与实施

本轮按已评估的 B → C → A 顺序收敛，不按作品名写特例，不引入解析依赖，不开启 AI，不执行媒体修复。

1. B：精确官方预览区分正片和同目录、同存储、唯一关联的配套附件。附件不进入正片计数或修复范围；外来视频、外来字幕、重复和跨存储仍拒绝。结构化季集字段优先，缺字段和显式空值分开，明确词法冲突不忽略。请求、合同、附件与正片错误分列，坏合同不能缓存为成功。
2. C：基础 movie/tv 与业务细分类分开；目录显示名与路径片段不再作为类型证据。扫描根可去重，判定保留完整规则和官方实际选中策略的最小指纹。既有链接、期望目标缺失、候选未证实分列；路径偏差不冒充从未整理，同样不被压成正常。
3. A：保留 SDK 多语言、容器真人版和年份来源。仅 SDK 明确认出的发布组可降为弱线索，弱括号可以辅助查询但不能独自确认。强标题组仍须全部被数据库详情解释。候选去重、廉价类型/年份排除与详情核验分开；详情最多三项，未查完明确预算不足，不宣称没有匹配或唯一正确。单个竞争项请求失败不终止其他项，也不能视为已排除。

前端仅更新版本号，沿用原布局与颜色。构建生成的新版本资源与历史版本资源并存，避免构建默认清空 dist 带来的无关删除。

## 交付与现场验收

用户已明确授权 PR/CI/合并及先公开“只读试用、AI 关闭、尚未 NAS 验收”，然后安装同一包只读回归。此处为公开顺序例外，不等于真实验收通过。候选从干净已提交源码打包，记录源码 SHA 与 ZIP SHA-256；先存为 draft，合并后提升同一制品，远端下载再核对哈希。

现场沿用 5.1.4 同批真实样本和原 33 个重点对象，检查正常电影/剧集、未证实关联、已知错分类，以及别名、原盘、多季、推断集号和详情冲突形状。保持 AI 关闭、只读，不制造缺集、不改文件。完整公开、安装、运行身份和识别结果另留本地回执；未完成前不得把本地绿灯称为识别关通过。

## 保留的限制

未知发布组污染、数据库缺少别名或竞争项未核验仍可能未决；不以模糊匹配消掉未知。原盘不进入逐文件全库配对。细分类策略证据不足仍未决，不声称所有同 tv 分类正确。物理关联不足不能推导下载缺集或历史从未整理。
