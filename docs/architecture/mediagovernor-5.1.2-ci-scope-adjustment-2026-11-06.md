# 5.1.2 依赖 CI 范围调整

本轮目标仍是只读识别现场验证。用户已允许先公开同一 5.1.2 只读试用制品，再在 NAS 安装验证，AI 关闭，不执行媒体修复；同时允许修正不必要的跨平台排队。

原 CI 在五平台 runner 内判断是否需要安装依赖，因此未改依赖仍会申请 macOS arm64 机器。GitHub 两次报告该平台 capacity constraints，任务没有 runner、没有测试步骤便结束。本次将差异判断移到独立 Linux job，再以 job-level if 决定是否申请五平台 runner。

真实依赖安装的触发范围是 `plugins.v3/*/pyproject.toml` 或 `scripts/check_v3_dependency_install.py`。工作流和测试文件本身的变化由现有 Plugin test gate 中的 CI 合同测试验证；不再将其一律解释成运行时依赖变化。本次保留原五平台矩阵、uv 版本/解释器版本及真实安装命令。以后修改安装器或依赖声明仍须运行五平台；若要修改平台/解释器/安装命令，应显式评估并验证受影响平台，不能以本次编排调整为由宣称其已通过真实安装。

新增稳定的 V3 dependency gate 汇总检查：仅接受“范围判断成功且无需安装、矩阵确实跳过”或“需要安装且矩阵成功”；范围判断失败、未知输出、矩阵失败/取消或意外跳过均失败。没有删除苹果支持，没有将跳过说成安装测试通过。现有后端、前端、识别和包检查继续执行。

本地定向验证执行工作流中的真实 Bash 脚本：以临时 Git 仓验证相关/无关文件差异、依赖删除及无效基线；执行汇总脚本验证成功、失败、取消、意外跳过和未知输出。GitHub 自身的 job 调度与依赖关系仍须由新提交的真实 CI 证明。
