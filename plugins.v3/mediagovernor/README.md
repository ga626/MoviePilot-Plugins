# 媒体治理（MediaGovernor）

MediaGovernor 是 MoviePilot V3 整理链路的最后一道质量检查。它不接管下载或整理，而是逐条核对 MoviePilot 已记录的历史信息，再按作品汇总需要复核的结论。

## 它怎样工作

1. 在 MoviePilot 的“插件”中打开“媒体治理”。
2. 点击“**开始检查全部**”。页面会显示已完成数量、总数量和进度条；每完成一条都会保存。检查较慢时可以暂停，稍后从下一条继续；完成后点击“**再次检查全部**”即可开始一轮新的检查。若升级或新历史记录导致检查范围变化，页面会保留旧结论并明确提示“检查范围已变化”，不会把旧进度伪装成当前全部完成；此时点击“**重新检查全部**”才会建立新的完整检查轮次。
3. 插件会读取 MoviePilot 已保存的历史信息，逐条确定作品名称、年份和类型；只保存检查结论，不保存原始文件名或路径。
4. 检查完成后，同一电影、剧集或动漫会合并为一张卡。卡片会分别列出每类结论及其对应记录数量：
   - **整理方式与硬链接策略不一致**：历史记录显示为复制、移动等方式。这是历史记录事实，但不等于插件已经验证实际文件错误；
   - **整理方式未记录**：没有足够证据确认当时是否硬链接；
   - **补建前检查未通过**：原整理失败，但 MoviePilot 的安全预演暂时不能补建；
   - **可安全补建硬链接**：原整理失败且零写入预演通过，才会进入确认后的单条处理流程；
   - **信息不足**：没有可靠作品身份，只汇总数量，不伪装成某部影片。
5. 一张作品卡中若有可补建的失败记录，可以先点击“**一键生成修复方案（不改文件）**”。只有通过预演的记录会进入下一步；点击“**确认修复**”后，系统才会为这一作品内的这些记录创建硬链接。

检查会读取 MoviePilot 的历史记录，并可能使用你已经配置好的媒体识别来源或辅助识别能力补齐作品身份；它不会下载影片、修改下载器、代理或原有整理规则，也不会移动、删除、改名、覆盖或创建媒体文件。

## 为什么先检查、后展示

历史失败记录只能说明“当时有异常”，并不等于现在仍然有问题；同样，历史里的整理方式也不能替代对实际文件的验证。插件会先把每条记录核查一遍：能确认无需复核的记录不会变成卡片；没有证据的情况会明确标为“待复核”，而不是假装成已经确认的错误。

## 无法自动处理时

点击卡片中的“查看详细结论”，再展开“为什么这里不能直接一键修复所有项目？”：

1. 在 MoviePilot 搜索页确认作品、年份和类型。
2. 在整理或历史记录中确认它是否已经入库；已入库就无需处理。
3. 若检查明确提示“信息不足”，说明 MoviePilot 历史中没有足以确认作品身份的线索。插件不会猜测、不会把原始文件名当成片名，也不会改动文件；补齐可识别信息后，再重新执行一键检查。

## 安全边界

- 不移动、改名、删除、重试或覆盖文件；
- 不修改下载器、代理、下载目录或 MoviePilot 原生整理规则；
- 不保存或返回媒体路径、下载路径、Cookie、令牌、PT 链接或完整文件列表；
- 不为某一部作品写专属规则；身份不可靠时不会猜测。

硬链接只会在单条记录已通过模拟检查、并由用户在确认窗口再次确认后创建。新的模拟检查结果会作废旧的待执行方案，避免旧状态被误用。

## 开发与发布

本插件遵循 MoviePilot V3 的 `plugins.v3/`、`tests/v3/` 和 `package.v3.json` 合同。复杂交互使用官方 Vue 模块联邦，构建产物位于 `dist/assets/`。提交前至少运行定向 Python 测试、前端构建、版本门禁和真实 V3 宿主加载验证。
