# 媒体治理（MediaGovernor）

MediaGovernor 是 MoviePilot V3 的媒体整理质检台。它不接管下载，也不替代 MoviePilot 的识别和整理；它在整理之后，把能够证实的问题按作品合并出来，帮助用户安全地重新整理。

## 使用方法

1. 在 MoviePilot 的“插件”中打开“媒体治理”。
2. 点击“开始检查全部”。这会建立一轮新的、可重复的检查；页面会显示实际进度，可以暂停并在之后继续。
3. 检查完成后，只会出现有明确证据的作品卡。历史记录缺字段、或历史上曾使用其他整理方式，都只算“历史资料说明”，不会伪装成影片故障。
4. 打开一张卡片，先看作品、问题类别和源/目标文件数量摘要。
5. 若卡片允许处理，点击“生成整理方案（不改文件）”。可以让 MoviePilot 按当前规则选目录，或从 MoviePilot 当前配置的媒体库目录中选择一个目标。
6. 预演通过后，点击“确认重新整理”。这一步才会调用 MoviePilot 原生整理来建立缺失的展示入口。

## 会检查什么

- 原整理失败但原始文件仍可读取；
- 目标入口缺失；
- 源包与目标包的视频数量或已识别集号存在可证明的差异；
- 原生预演拒绝执行、作品身份无法可靠确认等安全阻断。

同一作品的相关记录会合并在同一张卡片中。字幕和视频分别统计；只有源和目标都可读取、且差异明确时，才会显示“文件未完整整理”或“剧集未完整整理”。

## 安全边界

- 检查和生成方案均不创建、删除、移动、重命名或覆盖文件；
- 真正执行前必须经过 MoviePilot 原生预演和用户再次确认；
- 原始下载文件不会被本插件移动、改名或删除；
- 目标目录每次从 MoviePilot 当前配置读取，不写死目录名称或路径；目录配置改变后，旧方案不能直接执行；
- 插件不保存或展示媒体/下载路径、完整文件名、Cookie、订阅、代理、PT 信息或媒体内容；
- 插件不自动删除旧展示入口。涉及删除或覆盖的情况会停止在说明，不会隐藏在“一键修复”里。

## 已知限制

- “硬链接 inode 完全一致”没有稳定的 V3 插件合同，因此本插件不会把它宣传成已验证事实；
- “源包本来缺少的剧集”不能靠重新整理补回，只有源有、目标少的可证明差异才进入处理候选；
- AI 不会在全库检查中自动调用。当前版本只使用 MoviePilot 原生识别；若宿主未来提供稳定、可审计的第三方插件 AI 合同，才会在用户明确允许、具有预算与缓存保护时接入。

## 开发与发布

本插件遵守 MoviePilot V3 的 `plugins.v3/`、`tests/v3/` 和 `package.v3.json` 合同。提交候选时必须通过定向 Python 测试、前端构建、版本与联邦 CSS 门禁，并在真实 MoviePilot V3 宿主完成加载验证。
