# 媒体治理（MediaGovernor）

MediaGovernor 是 MoviePilot V3 的整理质量工作台。它只编排已登录 MoviePilot 的公开 API；不接管下载器、文件系统或硬链接。

## 先把范围查对

“开始检查”先读取当前已配置的媒体库与下载目录，直到找到直接含视频的目录即停止下探。平铺目录会按文件名拆成多个作品；失败和成功整理历史只用于交叉线索，绝不再充当检查范围。指向宽泛父目录的历史不会再被错误地当成一部作品递归扫描。

开始前可选本次最多检查 60、180 或 360 个包；重叠根目录会先合并。若当前账号能读取 `storage/directories` 和每个目录的 `storage/list`，页面会显示实际扫描到的库存包数。达到公开只读接口的安全扫描上限时，页面明确标为部分库存；不能读取时明确降级，不伪造库存结论。

## 找对作品

检查只把两类可证明信号送入问题队列：仍没有对应成功记录的当前失败整理，以及不同视频文件明确重复标为同一集。目录名与文件名不同、部分下载、集号间隔和已恢复的失败历史都只是线索，不会单独显示成问题。集号只接受 `S01E02`、`EP02` 或动画文件末尾 `[02]` 等明确格式，清晰度、年份等普通数字不会被当成集号。

结构正常的包不会调用模型或候选搜索，也不会显示成“问题”。问题包才会把**不含真实路径的名称和层级证据**交给当前 MoviePilot 已配置的模型；模型只能提出“这包可能是什么”。找对作品是为后续官方预览服务，不等于“发现问题”。

可疑包先调用一次 MoviePilot 原生文件识别，再按需用一条强线索做原生标题识别；两者都没有候选时才查询最多两个优先影视源。音乐/音频数据源、类型不符、年份冲突、候选总集数小于来源最大集号或明显少于视频数的候选会直接淘汰，不再让用户面对无关音乐或同名真人版。完整账本、实际检索线索和发送给模型的目录结构均可查看。

候选来自 MoviePilot 当前配置的数据源；配置了豆瓣时会显示“来源：豆瓣”，未配置时插件不会伪造豆瓣结果。任何标题、年份或集数冲突，或候选接近，都必须由用户查看详情确认，不能自动进入下一步。

模型调用复用 MoviePilot 已配置的智能助手，不新增 API Key，也不复制 AI识别增强插件。AI识别增强仍负责日常单标题兜底；MediaGovernor 负责本插件的整包判断，并且即使模型失败或放弃判断，仍会继续原生候选核验，不把普通搜索结果伪称为 AI 结论。同一插件会话内，相同的脱敏证据只调用模型一次，避免重复消耗。

## 看得见的验收

“验收样例”页提供正常单季、动画/真人版冲突、样片、无候选、部分下载和重复集六个脱敏固定样例。另有合同测试覆盖“目录名不同不报警、已恢复历史不报警、清晰度数字不伪造集号”。它们复用生产规则，不读取 NAS、不调用模型；任一固定样例或回归合同失败，都不应进入候选安装。

## 整理正确

页面只对已进入问题队列的当前包核对实际重复集号、视频数量和已确认作品总集数。部分下载和目录名差异不构成整理错误。作品未确认时，这一步锁定而不是猜测“整理正确”。

对通过身份核验的包，页面才依次请求：

1. `transfer/manual/history`：只读核对历史；
2. `transfer/manual/target-path`：读取当前目录规则；
3. `transfer/manual` + `preview=true` + `reorganize=false`：生成官方逐文件零写入预览。

页面展示官方每项计划的标题、季集和是否生成目标。只要规则不唯一、预览缺项、存在失败或重复集号，预览即标为锁定。

本版本没有“执行重整”或“删除旧硬链接”按钮。原因是当前官方预览不提供旧硬链接的逐项删除清单；插件不能猜测删除范围。只有未来在真实 MoviePilot 宿主以独立候选证明了“预览与实际删除完全一致”的合同，才可能在新的版本中提出受控执行方案。

## 安全和发布

- 检查、候选核验和预览都是零写入；
- 不保存或输出媒体/下载路径、完整文件名、Cookie、订阅、代理或 PT 信息；
- 前端构建和本地合同测试不替代真实 MoviePilot/NAS 的加载和预览验收；
- 发布只提升同一已验 ZIP，并核对远端下载哈希和稳定安装回执。
