# 媒体治理（MediaGovernor）

MediaGovernor 是 MoviePilot V3 的整理质量工作台。它只编排已登录 MoviePilot 的公开 API；不接管下载器、文件系统或硬链接。

## 先把范围查对

“开始完整检查”读取全部可访问的媒体库与下载目录。平铺目录按文件名拆成多个作品；包含子目录的作品包递归读取完整结构。成功和失败整理历史按来源文件精确交叉核验，不能再用同一父目录的某次成功把另一条失败历史吞掉。

没有 180 个包或 4000 个目录项的截断。重叠根目录会先合并；任何目录、完整包或当前硬链接目标不可读，页面只会报告“未核验”，不会给出全量通过结论。

## 找对作品

每个完整可读包都会统一交给 MoviePilot 已配置的模型判断，而不是先用两条规则把它排除。模型判断会同现有整理的标题、年份、类型交叉比对；无整理记录、身份未核验、标题/年份/类型冲突、当前目标缺失或不可读都会进入问题队列。集号只接受 `S01E02`、`EP02` 或动画文件末尾 `[02]` 等明确格式，清晰度、年份等普通数字不会被当成集号。

模型只接收**不含真实路径的名称和层级证据**，只能提出“这包可能是什么”。模型与现有整理身份一致、当前目标可读且无结构冲突的包才被记为“身份一致”；这不等于已执行修复。

可疑包先调用一次 MoviePilot 原生文件识别，再按需用一条强线索做原生标题识别；两者都没有候选时才查询最多两个优先影视源。音乐/音频数据源、类型不符、年份冲突、候选总集数小于来源最大集号或明显少于视频数的候选会直接淘汰，不再让用户面对无关音乐或同名真人版。完整账本、实际检索线索和发送给模型的目录结构均可查看。

候选来自 MoviePilot 当前配置的数据源；配置了豆瓣时会显示“来源：豆瓣”，未配置时插件不会伪造豆瓣结果。任何标题、年份或集数冲突，或候选接近，都必须由用户查看详情确认，不能自动进入下一步。

模型调用复用 MoviePilot 已配置的智能助手，不新增 API Key，也不复制 AI识别增强插件。AI识别增强仍负责日常单标题兜底；MediaGovernor 负责本插件的整包判断，并且即使模型失败或放弃判断，仍会继续原生候选核验，不把普通搜索结果伪称为 AI 结论。同一插件会话内，相同的脱敏证据只调用模型一次，避免重复消耗。

## 看得见的验收

“验收样例”页提供正常单季、动画/真人版冲突、样片、无候选、部分下载和重复集六个脱敏固定样例。合同测试还覆盖“未核验不能通过、年份/类型冲突必须报警、覆盖不完整不能称为全量”。它们复用生产规则，不读取 NAS、不调用模型；任一固定样例或回归合同失败，都不应进入候选安装。

## 整理正确

页面只对已进入问题队列的当前包核对完整包结构、当前硬链接目标、重复集号、视频数量和已确认作品总集数。作品未确认时，这一步锁定而不是猜测“整理正确”。

对通过身份核验的包，页面才依次请求：

1. `transfer/manual/history`：只读核对历史；
2. `transfer/manual/target-path`：读取当前目录规则；
3. `transfer/manual` + `preview=true` + `reorganize=false`：生成官方逐文件零写入预览。

页面展示官方每项计划的标题、季集和是否生成目标。只要规则不唯一、预览缺项、存在失败或重复集号，预览即标为锁定。

预览完整后，只有用户二次确认才会调用 MoviePilot 官方重整。插件不自行删除文件：由 MoviePilot 依据命中的成功历史清理对应旧媒体库硬链接，再从下载原文件重建；下载原文件不在此操作范围内。

## 安全和发布

- 检查、候选核验和预览都是零写入；
- 不保存或输出媒体/下载路径、完整文件名、Cookie、订阅、代理或 PT 信息；
- 前端构建和本地合同测试不替代真实 MoviePilot/NAS 的加载和预览验收；
- 发布只提升同一已验 ZIP，并核对远端下载哈希和稳定安装回执。
