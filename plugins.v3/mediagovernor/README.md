# 媒体治理（MediaGovernor）

MediaGovernor 是 MoviePilot V3 整理后的质量工作台。它不接管下载或文件系统，只编排已登录 MoviePilot 的公开 API。

## 两个工作台

### 1. 找对作品

点击“开始检查”后，页面只读取 MoviePilot 已保存的失败整理历史，会先明确显示记录总数；相同来源包合并成一项后，最多三包并发处理并逐项显示：范围、总包数、已完成数、当前阶段、耗时和四种结论。它不是扫描整个媒体库。可暂停、继续或停止；停止只是不再派发新包，已经完成的结果会保留。

每个来源包先做有限、只读的目录抽样，提取视频/字幕/NFO 数量、季集模式和名称线索；再调用 MoviePilot 原生识别、当前已注册的媒体数据源搜索与候选详情。候选会直接展示中文名、原名、英文名、别名、数据源、类型、季集、支持依据和冲突。候选必须同时经标题、年份、类型和集数规模核验；翻拍、真人版/动画版、年份或集数冲突会变成“待你选择”，不能直接进入整理。

页面不保存或展示真实路径、完整文件名或媒体内容。已启用的 AI 识别增强仍可按 MoviePilot 原生识别链参与单标题识别，但不是本插件的硬依赖，也不拥有写入权限。

### 2. 整理正确

只对已确认身份开放。它依次调用 MoviePilot 官方的：

1. `transfer/manual/history`：确认是否命中旧成功整理历史；
2. `transfer/manual/target-path`：确认当前目录规则能否给出唯一目标，并将同一目标规则带进预览和执行；
3. `transfer/manual` + `preview=true` + `reorganize=true`：生成零写入逐文件方案。

只有旧成功历史存在、目标唯一、预览完整、没有失败项或重复集号时，才显示“确认重整此包”。确认后才调用同一官方入口的 `reorganize=true`。旧硬链接的清理完全由 MoviePilot 执行；插件从不直接删除、移动、改名或覆盖来源文件。

## 安全边界

- 检查、候选核验和官方预览均为零写入；
- AI 或单个搜索命中不能直接成为执行身份；
- 目录规则变化、来源不可读、候选冲突或预览不完整时，执行按钮保持锁定；
- 不保存媒体/下载路径、完整文件名、Cookie、订阅、代理或 PT 信息；
- 每次真实重整仍需要用户在页面内确认；真实媒体写入的宿主验收另需明确授权。

## 开发与发布

提交候选需通过前端构建、定向合同测试、版本和联邦 CSS 门禁。发布只提升同一已验 ZIP；安装前应在真实 MoviePilot V3 宿主完成页面加载和零写入预览验收。
