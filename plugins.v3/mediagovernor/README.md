# 媒体治理（MediaGovernor）

MoviePilot 原生整理之后的兜底：从下载原件出发，检查媒体库对应入口，发现缺失、错身份、错分类、错季集和额外错误入口，再按用户确认的计划修复。历史只提供线索，不能证明当前文件正确。

## 5.1.1 本地候选流程

1. 读取当前目录配置并枚举下载文件和媒体库，完整清单保存在插件私有 SQLite，不发送给 AI。读取异常、停止、未处理和上轮结果分别显示，不能把失败当空目录。
2. 独立下载容器及子目录仅作来源边界，不凭历史编号决定作品归属。混包可整簇或逐文件指定，人工归属持久保存，孤立字幕也保留。
3. 先发现物理关系。同一宿主本地文件可用 lstat(dev, ino) 缩小候选，不可用则回退大小筛选；最终仍用公开 SDK 逐对核验。符号链接、非本地和未证实关系不升级成确定结论。分页每页有界、同一任务自动继续；覆盖按不同源视频统计，不拿关系对数充当集数。
4. 公开 SDK 本地解析标题季集，再通过宿主识别和数据库取得候选。同容器多个 SDK 锚点可补充裸数字尾集的搜索线索，不把推断集号当执行映射。电影同名不同年、混包和解析失败仍保留歧义。
5. 用户最终确认一次并保存。movie/tv 与动画等类别分开；保留 genre 结构、S0、剧集组和集数格式。单项确认只重读受影响源容器，不重新发现全库；扫描中确认进入持久局部重查队列。
6. 已确认身份交给官方只读预览，逐源文件对账。正确入口缺失、错入口和占用独立记录。未计划附件单独说明；视频遗漏、范围外项目、多源冲突阻断计划。

AI 默认关闭。启用后仅在真正需要、无候选、无混包歧义且摘要未溢出时补充最多三个搜索词；不决定身份，不接收原始路径、文件列表或历史。每批最多四项、每任务最多八批只是预算上限，不是实测最优值。无供应商 usage 时记未知，不以字节数冒充计费 token。

## 操作和等待

- “检查现在”重新观察当前范围，复用未失效身份和预览，不是零 I/O。
- “重建全部基线”刷新自动候选和预览，仍保留有效人工确认。
- “停止检查”停止领取新工作，保留完成结果；同步宿主请求无法强杀，仍占最多八个全局只读配额，页面显示在途数量。
- 单项重查的缓存媒体库仅作候选，不能证明没有其他入口；全库覆盖由全局检查完成。
- 修复预览为后台只读任务，每服务最多两项，同作品重复请求复用，不长期阻塞前台。

## 修复安全门

默认 read_only=true，后端拒绝媒体修复。保存私有状态不是媒体写入；AI 外传由独立开关控制。关闭只读也不能跳过预览、清理许可和最终确认。

计划使用当前物理关系，历史不是清理前提；正确入口保留，缺失才建立。目标关系不明拒绝覆盖。生成及执行都核对人工身份、源范围、规则、实时文件指纹和目标，保护当前下载范围。许可单次消费，执行互斥。

官方 manual_transfer(preview=True) 计算目标。**不走 manual_transfer 的执行分支**：参考宿主该分支可能依旧历史跳过或自动清理。执行使用公开 TransferChain.transfer 单文件入口，采用官方预览给出的季集、双集范围、part 等，该入口自己的只读预览也必须与冻结目标完全一致。不改宿主，不调私有方法，不传强制覆盖，不把硬链接策略改成移动/复制。

全部新链接建立并回读证实后，才在单独许可下通过 StorageChain.delete_file 清理列出的旧文件。不用会治理父目录的 delete_media_file，不删除下载原件，不清父目录。失败保存部分完成回执，不宣布自动回滚；最终再回读新旧入口，随后局部重查。

宿主缺公开单文件入口、剧集季集不明确、目标不一致或文件变化时拒绝写入，不退回旧执行路径。

## 验证边界

后端生产路径由 pytest tests/v3/mediagovernor 覆盖，包含真实本地 SDK parser/MediaInfo、临时硬链接和参数传递；数据库及宿主执行在相关测试中为替身。

npm run test:contracts 的旧前端 helper 合同及 test:golden 历史场景仅作兼容回归，不能代替当前 Python 生产路径验证。真实 AppPage.vue 的本地模拟交互另验整簇选择、后台预览和清理确认门。

5.1.1 尚未公开、未在 NAS 安装或执行媒体修复。NAS 吞吐、完整真实样本准确率、模型费用及实际原生写入闭环未验。后续按同一源码/制品完成 PR、CI、授权安装、只读验收，再对获准的单项计划验证写入；本地通过不是用户验收。
