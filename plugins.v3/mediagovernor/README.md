# 媒体治理（MediaGovernor）

MediaGovernor 是 MoviePilot 原生整理之后的兜底：检查当前下载原文件与媒体库硬链接，找出“没有整理成功”和“表面成功但作品、分类、季集或层级错误”两类问题。

## v5 流程

1. 后端只读取 MoviePilot 当前配置中的下载目录、媒体库目录和整理历史；空路径与容器根目录会被拒绝。
2. 下载任务编号和独立目录仅作边界线索，不把历史身份当分组真值。混包允许人工选择文件归属，选择持久保存，未选文件继续留在待确认区。
3. 身份确认前先流式枚举媒体库，将文件元信息写入本地大小索引，再通过公开接口逐对核验；发现候选不依赖作品身份或可靠历史。候选分页和核验轮转进度持久保存；找到正确入口后仍查额外入口。大小只是筛选条件，不是同一文件的证明。
4. 原生识别、规则提取和数据库查询先给候选；人工也可直接搜索数据库。AI 默认关闭，启用后仅在没有候选、摘要未溢出且没有混包歧义时补充搜索词。只发送标题族、年份、季集等摘要，不发送完整路径、原始文件列表或整理历史。每批最多四项、每轮至多八批是当前上限，不是实测最优比例；实际 usage 缺失时记未知。AI、数据库和原生识别异常分别保存，数据库失败不当作空结果继续消耗 AI。
5. 候选最终由用户确认，人工选择绑定源文件集合，未变化时复用。已确认作品使用 MoviePilot 官方逐文件预览，再核对当前物理关系与预期目标；纯路径/命名差异不证明错作品。False、复制、读取异常和非本地存储均不能单独证明整理失败。预览遗漏文件或出现范围外文件时阻断强结论。
6. 每部作品的身份、预览、关系和结论在 IO 完成后一起提交 SQLite；一部失败不会丢掉其他结果。取消和进程中断保留已完成结果，下次重新枚举当前范围，复用仍有效的身份和预览，再核验当前关系；尚未实现目录枚举页游标的断点恢复。高级“重建全部基线”会刷新原生身份和预览，人工确认身份仍保留。

本地开发中的检查合同：命名规则、完整目录匹配规则与顺序、季号和文件集合变化会使相关 preview 失效；目录枚举顺序不会使缓存失效。候选负结果一小时后允许重试，日常复查不会延长该期限。每个服务最多 8 个在途只读 helper，超时不释放仍在运行的配额；结果迟到不能提交账本。每部作品每轮最多核验 64 个候选对，超限保留为 pending 并优先续查。

覆盖范围包括当前库索引发现的候选，不再仅限旧历史/预期目标；仍不声明全库额外链接已查全。页面区分待读、未知和已证实关系。已知额外错误目标持续复查；正常旧链接因新规则改变位置时进入“规则变化待确认”。上述改动仍是本地未发布源码，NAS 运行合同与耗时尚待同一候选只读验收。

结果分为：已经证明的问题、需要确认、本轮没读完。应有入口当前缺失不证明过去的原生执行失败，也不能替用户决定补回主动删除的文件。

本地身份安全修订：服务初始化时将旧版自动确认降回候选，撤回其派生结论及修复预览，保留候选与待复核关系；既有人工确认保持有效。源范围未读完整或候选所对应的文件已变化时不能确认。扫描期间的新人工选择优先，迟到核对结果不能覆盖它。

## 修复安全门

5.1.0 候选默认开启 `read_only`：检查、搜索、人工确认与预览可用，后端拒绝执行修复，页面不提供最终执行按钮。该开关是媒体写入开关，不阻止插件保存私有状态或查询公开元数据；AI 外传由独立开关控制。NAS 只读验收时保持只读开启、AI 关闭。关闭只读也不能跳过逐项预览和确认。

生成与执行修复预览都要求当前有效的人工身份确认；预览后身份选择改变、源范围不完整或文件指纹变化时必须重新检查和生成预览。

修复前会再次生成完整成功的官方预览，并记录原文件、可归因旧目标、新目标的实时指纹与同对象状态。现有目标关系未证实则拒绝覆盖或清理。最终确认时再次读取三者并重新运行官方预览；变化使 token 失效。执行仍由 MoviePilot 官方整理链完成，不默认强制覆盖。只有成功历史明确指向、位于当前媒体库且关系已证实的旧目标才可申请清理，还需用户单独批准。许可单次消费、并发执行互斥，部分失败保留逐项回执。执行后还须证实新目标与源文件同对象、旧目标已消失，再进入单项复核。插件不会删除原始下载；无历史旧入口清理及真实宿主修复合同仍未验。

## 验收

- `pytest tests/v3/mediagovernor`：v5 后端、真实 V3 导入、任务隔离、AI 批次、修复过期和一次性确认。
- `pnpm test:contracts` 与 `pnpm test:golden`：58 个前端规则合同和 47 个脱敏基线场景。
- 本地合同和构建不是用户体验验收；新发现的真实案例应先脱敏加入固定回放，再修改判断规则。
